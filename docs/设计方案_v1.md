## 二、Prompt 改造（治"冗长"的根）

### 病根

现在的 system prompt 强制要求**必须按 8 段结构回答**。模型只能照做——于是把一个小问题撑成论文，为了填满段落还重复论点。
**这不是模型的锅，是 prompt 的锅。**

### 改造后的规则（可直接评审）

```
先判断问题类型，再决定讲几段（不要固定 8 段）：
· 词性 / 搭配 / 单点疑问 → 3 段：一句话答案 → 为什么 → 一组对比
· 结构 / 语序 / 从句 / 时态等需要拆解的 → 最多 6 段

硬约束：
1. 每个事实只说一次，后文不得重复已建立的结论
2. 不涉及语序变化，就不写"还原正常语序"这一段
3. 术语全文统一，第一次出现时给中文解释；不引入学生没问的概念
4. 总长控制在 400 字以内（学生明确要求详细时才展开）
5. 最后必须给一个「现在轮到你了」的任务：指定话题 + 指定句式，让学生写一句
```

### 效果预期（同一个问题）

| | 现在 | 改造后 |
|---|---|---|
| 篇幅 | 约 1500 字 / 8 段 | 约 300 字 / 3 段 |
| 重复 | 同一结论出现 4 次 | 0 次 |
| 无用段落 | "本句没有发生倒装"仍写一整段 | 自动省略 |
| 字数级别标注 | 标在这次提问上（逻辑错位） | 标在**要学的句式**上："该句式 6 分" |
| 结尾 | 讲完就结束 | 强制一个仿写任务 |

### 新增：即时仿写闭环（闭环的最后一块）

学生写完一句 → 提交 → AI 只做三件事：判对错 / 给修正版 / 一句话原因。
判定结果直接回流知识库（对 → 已掌握，错 → 纠错）。

**为什么这条最重要**：现在学生"懂了"但没"用过"，你的产品定位是闭环，这一步才真正闭上环。
对面试也最值钱：能讲"我把学习闭环从'讲'补到了'练'"。

## 三、信息架构改造

| 现在 | 改成 | 为什么 |
|---|---|---|
| 「入库 / 出库」两个并列面板 | 「学会 → 写 → 看反馈 → 复习」单列任务流 | 入库/出库是**你的系统模型**；学生的心理模型是"我该学什么 / 我写得怎么样" |
| 设置条常驻顶部（Key、语音语言） | 收进「设置」页 | 低频配置不该占据首屏 |
| 知识库挤在左下角 | 独立「知识库」标签页 | 它是学习成果，值得独立空间 |
| 打开后就两个大输入框 | 步骤编号 + 快捷示例 chip | 告诉用户"现在先干嘛"，降低启动成本 |
| 三个操作区视觉权重相同 | 反馈按重要性排序（切题 → 句式 → 语法） | 雅思评分维度里 Task Response 权重最高，视觉排序应一致 |

导航：**学习 / 知识库 / 设置** 三个标签（移动端底部固定主按钮，桌面端顶部标签）。

## 四、视觉系统（从"工程师审美"到"阅读优先"）

### 字号（最关键的改动）

| 用途 | 现在 | 改成 |
|---|---|---|
| 正文 / AI 讲解 | 11-12px | **14.5-15px** |
| 卡片标题 | 13px | 15-16px |
| 页面主标题 | 15px | 17-18px |
| 辅助信息 | 10-11px | 12px |
| 按钮文字 | 11-12px | 14px（点击区 ≥42px） |

> 现在 11px 的正文放在手机上基本没法读——这是"能用但不舒服"的最大来源。

### 颜色

| 角色 | 值 | 用途 |
|---|---|---|
| 主色 | `#1E6F5C`（墨绿） | 主按钮、已掌握、正确 |
| 主色浅底 | `#E8F3EF` | 讲解卡、成功块 |
| 信息蓝 | `#2C5AA0` | 6 分标注、题目理解 |
| 警示琥珀 | `#8A5A00` | 句式提醒 |
| 错误红 | `#A33A2A` | 语法问题、纠错 |
| 语言点紫 | `#5B4FA8` | 语言点 / 切题判断 |
| 中性 | `#F6F6F3` / `#E7E6E1` / `#565C55` | 背景、描边、次级文字 |

三条原则：
1. **只保留一个主色**（现在是 8 个颜色平权，没有视觉锚点）
2. **层级靠留白和字号，不靠边框堆叠**
3. **颜色只表达语义**（对/错/提醒），不用于装饰

### 组件规范

| 组件 | 规格 |
|---|---|
| 卡片 | 圆角 14px、白底、1px 描边、极轻阴影（`0 1px 2px rgba(0,0,0,.03)`） |
| 主按钮 | 高 42px、圆角 10px、墨绿底白字、字号 14 |
| 次按钮 | 同尺寸、白底描边 |
| 标签 chip | 圆角 999px、字号 12.5、内边距 5×11 |
| 反馈块 | 左侧 3px 语义色边 + 浅色底（比现在的整块填色更克制） |
| 空状态 | 虚线框 + 一句"下一步做什么" |

## 五、移动端 + PWA

### 移动端
- 单列布局，正文 15px，行高 1.65
- 底部固定主按钮（"检查我的作文"），拇指可达
- 所有可点元素 ≥42px
- 输入框聚焦时不缩放（字号 ≥16px 的输入框策略）

### PWA（替代小程序）
- `manifest.webmanifest`：名称、图标（192/512）、主题色、`display: standalone`
- Service worker：缓存页面与图标 → **离线也能打开**（AI 仍需联网）
- 效果：手机浏览器"添加到主屏幕" → 有图标、全屏、无浏览器地址栏，体验接近原生

### 为什么不做微信小程序（三条硬约束）
1. **审核**：微信对生成式 AI 类目要求主体资质（算法备案等），个人主体基本过不了
2. **架构冲突**：小程序无法沿用"用户自备 Key 直连"，必须改回服务端持有 Key → 成本、被刷风险、备案问题全部回来
3. **成本**：要重写一遍 UI（WXML/WXSS），现有 HTML/CSS 不能复用

> 什么时候才值得做小程序：当你需要**微信内社交传播**（分享卡片、群打卡）或**微信登录/支付**时。现在的目标是"面试官和同学打开就能用"，PWA 足够。

## 六、需要你拍板（8 个点）

| # | 决策点 | 我的建议 |
|---|---|---|
| 1 | 导航：单列任务流 vs 保留双栏 | **单列任务流**（学生视角） |
| 2 | 主色：现有蓝 `#185FA5` vs 墨绿 `#1E6F5C` | **墨绿**（学习/成长语义，且避开雅思工具千篇一律的蓝） |
| 3 | 是否弃用"入库/出库"这两个词 | **改成「学会 / 写 / 复习」**；如果你喜欢"库"的隐喻，可保留为副标题 |
| 4 | 讲解长度：自适应 3-6 段 vs 固定 8 段 | **自适应**；若你想保留"系统感"，可让用户切换"精简 / 详解" |
| 5 | 即时仿写闭环要不要做 | **做**——这是闭环最后一块，也是面试最好讲的点 |
| 6 | 知识库独立成标签页 vs 留在主页面 | **独立标签页** |
| 7 | PWA 要不要做 | **做**（半小时，手机上体验立刻不同） |
| 8 | 是否保留现在的暖白背景 `#F7F7F4` | 建议保留（比纯白护眼，样稿用的是 `#F6F6F3`） |
